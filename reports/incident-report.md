## 2. Executive Summary

During security monitoring of the Ubuntu Server, multiple failed SSH password authentication attempts were identified from the Kali Linux lab workstation.

Three failed authentication events were observed against the lexa account from source IP 192.168.56.20.

The investigation correlated the failed authentication events with existing successful SSH authentication events and reviewed privileged command activity on the Ubuntu Server.

Based on the available evidence, no successful compromise was established following the observed failed authentication attempts.

This activity was intentionally generated within an isolated VirtualBox laboratory environment to simulate a real-world SOC investigation scenario.

## 4. Investigation Findings

### 4.1 Source IP Analysis

The failed SSH attempts originated from:

192.168.56.20

This address belongs to the Kali Linux workstation used as the attacker/test system in the controlled lab.

A source-IP frequency analysis identified three failed authentication events from this address.

### 4.2 Target Account

The targeted account was:

lexa

The authentication failures were password-based SSH authentication attempts.

### 4.3 Successful Authentication Correlation

The SSH journal contained successful authentication events involving the same source IP.

However, the successful events occurred before the later controlled failed authentication attempts.

The investigation did not identify a successful authentication immediately following the observed failed attempts.

Therefore, the available evidence does not establish that the failed attempts resulted in unauthorized access.

### 4.4 Privileged Activity

Sudo activity was reviewed through /var/log/auth.log.

The account lexa was observed executing commands through sudo, resulting in USER=root.

The observed privileged commands were analyst-generated investigation commands such as:

- journalctl
- grep
- ss
- whoami

These commands were executed as part of the security investigation and were not considered malicious activity.

## 8. Analyst Conclusion

The investigation identified three failed SSH password authentication attempts against the lexa account from the Kali Linux source IP 192.168.56.20.

The events were successfully detected and correlated using Linux authentication logs and the SSH system journal.

The investigation also reviewed privileged activity and confirmed that observed sudo commands were generated by the analyst during the investigation.

Based on the collected evidence, there is no sufficient evidence to conclude that the failed authentication attempts resulted in successful unauthorized access.

The incident is therefore classified as:

*Repeated Failed SSH Authentication / Suspected Brute-Force Activity — No Confirmed Compromise*

## 9. Recommended Response Actions

In a production environment, a SOC analyst could recommend:

1. Monitor the source IP for additional authentication attempts.
2. Review successful SSH logins associated with the targeted account.
3. Verify whether the targeted account is expected to use SSH.
4. Enforce strong password policies.
5. Prefer SSH key-based authentication over password authentication.
6. Disable direct SSH access for unnecessary accounts.
7. Implement account lockout or rate-limiting controls where appropriate.
8. Deploy centralized SIEM monitoring for SSH authentication events.
9. Configure alerting for repeated authentication failures.
10. Investigate any successful login occurring immediately after repeated failures.
